# Maintainer scripts

The working repository is private. The public repository,
`github.com/IZZY-Agency/quartermaster`, receives snapshots exported by
`publish.sh`, and releases are built from the public repository. The publish
and release scripts are ported from sitboard's and adapted.

| Script | What it does |
|---|---|
| `check-private.sh` | Fails when private material is in the tree, the history or a text file. `--help` lists the modes. |
| `make-denylist.sh` | Builds the private deny-list of names that `check-private.sh` uses, outside the repository. |
| `publish.sh` | Exports the allowlisted tracked files into a checkout of the public repository and runs the gates; commits only with `--commit` or `--update`. |
| `package.sh` | Builds the four release archives (`qm` with `LICENSE`, `THIRD_PARTY_NOTICES.md`, `README.md` and the qm-worker plugin; the macOS ones also the Swift helper `qm-privcheck`) and their `.sha256` files (`make release`). |
| `notarize.sh` | Notarizes a Developer ID-signed macOS binary; `package.sh` calls it for `qm` and `qm-privcheck`. |
| `verify-release.sh` | Checks the archives and runs those this machine can run (`make verify-release`). |
| `render-formula.sh`, `formula/quartermaster.rb.tmpl` | The Homebrew formula for one release. |
| `release.sh` | Builds, verifies and publishes the GitHub release from the public repository at the tag. A dry run unless given `--go`. |
| `tap.sh` | Writes the formula into the tap checkout from the published release, and commits. |
| `notices.sh` | Writes or checks `THIRD_PARTY_NOTICES.md` with `internal/tools/notices` (`make notices`, `make notices-check`). |
| `*_test.sh` | The tests of these scripts; `make check` runs them. |

`internal/tools/sweep` (`make sweep`) is the optional semantic sweep before a publication; see [Semantic sweep](#semantic-sweep).

The release tests run on macOS through `make check`. To run them on Linux as well, commit first, then:

```sh
make release-test-linux
```

It clones what is committed into a temporary folder and runs `make release-test` and the guard's tests in a `golang:1.27` container (another image: `make release-test-linux LINUX_IMAGE=…`). A plain clone is needed because a worktree's `.git` file points at a host path the container cannot see. Uncommitted changes are not tested, and the target says so when there are any. The tests pack the macOS archives with a stand-in `swiftc`, so they run on Linux too; a real build of the helper needs a Mac.

## Third-party notices

`THIRD_PARTY_NOTICES.md` is generated by `make notices` and checked by `make check` (`notices-check`). It holds:

- Go's licence, pinned by digest, and the notices of other authors that the Go standard library carries for the four release platforms. All of them are listed, whether or not `qm` uses the package that holds them, so the file changes with a Go upgrade and not with each new import. Each notice text is pinned by digest in `internal/tools/notices`: a Go upgrade that changes one stops the generator until a person reads it and updates the pins.
- Every Go module in the build of `qm`, none today. A new dependency stops the generator until its licence is read and entered, with the digest of its licence file, in the `reviewed` table of `internal/tools/notices`.
- A line saying that the Swift helper links only Apple's system frameworks. `package.sh` checks that with `otool -L` when it builds the helper.

## What each private-material scan reads

| Command | Reads | Run by |
|---|---|---|
| `check-private.sh` | the work tree: every tracked or untracked, not ignored, file, and what is staged | `make check`, and `publish.sh` on the tree it exports |
| `check-private.sh --history --scope=branch` | everything reachable from HEAD, the local `main`, `origin/main` and every tag (tag names and annotated tag messages too), each back to its root, and those ref names. Other branches, the stash, notes and other refs are left out; its summary line names its scope and says how many refs it left out | `make check` |
| `check-private.sh --history` | everything reachable from every ref, and every ref name | `make private-all` on this repository, by hand; `publish.sh`'s gate on the public repository |
| `check-private.sh --history --pull-refs` | the same, and the heads of origin's pull requests | you, before going public (below) |
| `check-private.sh --text FILE` | one file, such as a pull request body or a commit message | you, before `gh pr create`; `publish.sh` on its commit message |

`make check` scans only the branch in hand, so another worktree's unfinished branch in the same repository cannot fail it. A scoped clean result is not the full one.

There is one release gate, in `publish.sh`, and its history scan runs on the public repository after the commit, so it never reads this repository's other branches. The full scan of this private repository is run by hand: `make private-all` (the tree and `--history` with the deny-list) before every publication, and `--history --pull-refs` before going public.

## Releasing a version

The version lives in one place: `RELEASE_VERSION` in the Makefile. `CHANGELOG.md` must open with its `## <version>` entry; `make check` enforces that (`changelog-check`). Every script below ignores your global and system git config and hooks, and none of them pushes.

1. **Export.** In a clean private tree, with a clone of the public repository next to it (its origin exactly `https://github.com/IZZY-Agency/quartermaster.git`):

   ```sh
   scripts/publish.sh ../quartermaster-public                 # stage, run the gates, show the tree
   PUBLISH_IDENT="Name <email>" scripts/publish.sh ../quartermaster-public --commit
   ```

   The export set is the allowlist in `publish.sh`: `.claude-plugin/marketplace.json`, `plugins/`, `cmd/`, `internal/`, `swift/`, `scripts/`, `testdata/` and `go.sum` when present, `go.mod`, `Makefile`, `LICENSE`, `THIRD_PARTY_NOTICES.md`, `README.md`, `SECURITY.md`, `CHANGELOG.md`, `.github/workflows/ci.yml`, `.golangci.yml` and `.gitignore`, as tracked. `docs/`, `.claude/`, `CLAUDE.md` and `AGENTS.md` are never in it; `.claude-plugin/` is another folder, and its marketplace is exported because users add the marketplace from the public repository. Every other tracked file must be kept back on purpose (`KEPT_BACK` in `publish.sh`: `docs/`, `.claude/`, `.codex/`, `CLAUDE.md`, `AGENTS.md`, `.env*` and keys): a tracked file that is neither exported nor kept back stops the run and is named, so a new file is never left out without a decision. A real run refuses while an allowlisted path is not tracked yet (go.sum and testdata/ excepted); only a stage-only rehearsal goes on and names them.

   It refuses before touching anything when:
   - the export set holds a `.claude`, `.codex` or `docs` folder at any depth, a `.env*`, key, certificate, credentials or database file, `CLAUDE.md` or `AGENTS.md`, a binary file, a file of a kind its folder does not export (`KINDS` in `publish.sh`), or a tracked file that `.gitignore` ignores;
   - an allowlisted path below the top level is not exactly one tracked file (a folder of that name would export what is inside it);
   - the target is, contains or sits inside this repository (by file identity), shares its git folder, or holds its history;
   - the target has uncommitted changes or stray files.

   The gates on the snapshot:
   - the staged files are exactly the exported ones, blob for blob;
   - no pointer to an unexported `docs/` file;
   - `check-private.sh` with the deny-list;
   - `make check PRIVATE_FLAGS=--no-denylist` and `make build` in a clean copy;
   - after committing, `check-private.sh --history` with the deny-list (the commit message too), and the commit is undone if that fails.

   `--commit` commits "quartermaster <version>" with the changelog entry and tags `v<version>`; `--update "<subject>"` commits between releases without a tag. Both mark the exported private commit with the local tag `last-published` and print the push command, which names the new commit by its id.

2. **Build and publish the release.** On a Mac, with the Developer ID identity and a notarytool profile (supplied at release time, never stored here):

   ```sh
   SIGN_IDENTITY="Developer ID Application: <team>" NOTARY_PROFILE=<profile> scripts/release.sh        # dry run: checks, plan, notes
   SIGN_IDENTITY="Developer ID Application: <team>" NOTARY_PROFILE=<profile> scripts/release.sh --go   # do it
   ```

   - **Refusals:** unless `v<version>` is on the public repository and no release of it exists.
   - **Build:** in a clone of the public repository at the tag, `make release`, which builds only there: `qm` for the four platforms and `qm-privcheck` for both macOS architectures (`swiftc -target`), each macOS binary signed and notarized.
   - **Verify:** `REQUIRE_SIGNATURE=1 make verify-release VERIFY_FLAGS=--rebuild` checks every archive's contents, the signatures and notarization of both macOS binaries, the tag's commit in `qm --version`, that `qm-privcheck status` answers (`available` or `unavailable: …`, either passes), and that a second build has the same bytes. The macOS archives are left out of that byte comparison, because a signature changes them; in an unsigned build they are compared entry by entry except `qm-privcheck`, because swiftc's output is not reproducible. Set `EXPECTED_TEAM_ID` to also check the team.
   - **Publish:** it copies the eight files to `bin/release/<version>/` here and runs `gh release create v<version> ... --verify-tag` with the changelog entry as notes.

   `PACKAGE_DEV=1 make release` makes a local test build anywhere (on a Mac: it needs swiftc), and `make verify-release PACKAGE_DEV=1` checks it; it is never a release.

3. **Tap.** With the eight files in `bin/release/<version>/` (so `tap.sh` can compare checksums):

   ```sh
   PUBLISH_IDENT="Name <email>" scripts/tap.sh ../homebrew-tap
   ```

   It downloads the published archives and refuses them unless they match both the published and the local `.sha256`. Then it writes `Formula/quartermaster.rb` (it installs `qm`, `qm-privcheck` on macOS and the qm-worker plugin into `share/quartermaster/plugins`), adds the README lines, runs `brew style` (on failure it puts the checkout back as it was) and commits. It prints the push command with the exact commit id.

## Semantic sweep

`check-private.sh` matches words; the sweep reads meaning. It asks Jev four questions about every comment and documentation paragraph of the export set, as committed at HEAD: does it tell the story of the development process, point at something the public cannot open, identify a private person, or help an attacker. It is optional and runs only with `TYPESAFE_API_KEY` (without it, it says so and exits 0):

```sh
make sweep                        # every exported file, before the first publication
make sweep SINCE=last-published   # only the files changed since the last publication
```

Each answer goes to `bin/sweep.jsonl`, and the hits at or above each question's review threshold are listed to read. It fails when a chunk could not be judged, or when an answer reaches 0.6 for security or 0.8 for a personal identifier; process narrative (from 0.85) and private references (from 0.8) are listed only.

## Going public

Before the repository or its history is published, run the history scan once more with the deny-list. Add the heads of every pull request, because GitHub keeps them under `refs/pull/N/head` even when no branch reaches them any more:

```sh
scripts/check-private.sh --history --pull-refs
```

`--pull-refs` fetches origin's `refs/pull/*/head` into `refs/check-private/pull/` for the run, says how many it fetched, and removes those refs afterwards. Run it in a full clone: the history scan refuses a shallow one.

No local scan can see everything GitHub still serves: commits that a force-push replaced, or that only deleted branches reached, can stay fetchable by commit id. That is one reason to publish a fresh snapshot repository, as `publish.sh` does, instead of making the working repository public.
